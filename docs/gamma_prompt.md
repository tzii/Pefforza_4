# Prompt for recreating the presentation with Gamma

> 🇮🇹 [Versione italiana](it/gamma_prompt.md) (generates the Italian deck)

## Recommended procedure

1. In Gamma choose **Create with AI > Paste in text**.
2. Pick a **14-card** presentation, **16:9** format.
3. Paste the prompt below.
4. Also upload `docs/presentation_outline.md` as reference text, if Gamma
   lets you add sources.
5. After generation, check slides 5, 7, 8, 9, 10 and 12 in particular:
   diagrams and flows must keep the technical order given.

## Prompt

```text
Create a professional 14-slide presentation in English about the project
"Pefforza 4", for a school/university presentation and a technical
portfolio.

GOAL
Explain, technically but accessibly, how the project connects a physical
Connect Four board to computer vision, an exact game solver, a learned
policy, augmented reality and voice. The central message: "perfect" is a
claim that must be measured, and the project's value comes from the
verifiable integration of perception, decision, interaction and
reliability, not from a single algorithm.

STYLE
- modern, clean, energetic, not corporate;
- 16:9 format;
- backgrounds alternating midnight blue/near black and warm ivory;
- palette inspired by Connect Four: cobalt blue, red, yellow, mint green;
- large, conclusive titles, not mere labels;
- little visible text, at most 3 ideas per slide;
- simple diagrams, 6x7 boards and AR arrows;
- no invented logos, stock photos, humanoid robots or generic AI icons;
- no repetitive card grids;
- use speaker notes or secondary text for details.

DATA THAT MUST NOT CHANGE
- Python 3.10-3.13;
- 3 modes: CLI, Pygame GUI, physical AR assistant;
- 5 difficulties: easy, medium, hard, impossible, neural;
- opening book: 533,468 positions up to ply 17, 950 KiB, generated by a
  native solver (Pascal Pons);
- exact oracle: 729 positions with the score of every column;
- share of value-preserving moves on game lines: impossible 100%,
  neural 96.3%, hard 90.8%, medium 77.5%, easy 65.6%;
- previous neural model (PPO vs random opponent): 59.7%;
- 273 automated tests, CI on Ubuntu (Python 3.10-3.13), Windows and macOS;
- computer vision: 6x7 board, nominal warp 700x600, ROI margin 20%,
  fill threshold 30%;
- vision: 1=red, 2=yellow;
- agents: 1=self, 2=opponent.

STRUCTURE OF THE 14 SLIDES

1. Cover
Title: "Pefforza 4"
Claim: "A physical board becomes an intelligent system."
Visual: Connect Four board with an AR arrow on column 4.
Metrics: 3 modes, 5 difficulties, 100% perfect moves.

2. The challenge
Title: "The problem isn't choosing a column. It's keeping four worlds
consistent."
Flow visual: physical reality -> visual perception -> rules and AI ->
user feedback.
Risks: noise, latency, tactical credibility.

3. Evolution
Title: "From monolithic demo to an installable, measured system."
Timeline:
- December 2025: PPO prototype + webcam + TTS, then physical board and
  calibration;
- May 2026: package, CI, tests, minimax, safety net and watchdog;
- September 2026: bitboard engines, reading validation, exact solver;
- October 2026: opening book + oracle, automatic board localization,
  lighting adaptation, solver-taught network.

4. Product
Title: "One engine powers three experiences and five levels of challenge."
Show distinct mockups for CLI, Pygame GUI and physical AR.
At the bottom: easy=random, medium=1-ply, hard=bitboard depth 8,
impossible=opening book + exact solver, neural=CNN distilled from the
solver.

5. Architecture
Title: "Offline work and runtime stay separate, but speak the same
language."
Two-lane diagram.
Runtime: webcam -> board localization -> warp + adaptive HSV -> validation
-> 6x7 grid -> agent registry -> AR + voice.
Offline: native solver -> opening book, oracle, teacher data -> distilled
CNN.
Book and CNN enter the agent registry as the impossible and neural tiers.

6. Game core
Title: "The 6x7 matrix is the shared contract of the whole system."
Visual: numeric board.
State: 42 cells 0/1/2.
Action: column 0-6, automatic gravity.
Reward: +1 win, 0 step/draw, -1 loss in the wrapper.
Illegal move: -10.

7. Perfect opening
Title: "Perfect play needs an opening book."
Visual: tree where the AI's moves are fixed and only the opponent branches,
up to ply 17.
Metrics: 533,468 positions, 950 KiB; before: only 4-56% of positions at
plies 8-13 provable in 3 s.
After the book the solver proves every move within about 3 s.

8. Measurement
Title: "Perfect is measured, not claimed."
Bar chart of value-preserving moves on game lines: impossible 100%,
neural 96.3%, hard 90.8%, medium 77.5%, easy 65.6%.
Explain: value-preserving = a won game stays won, a draw stays a draw.

9. Learning
Title: "The network learns from the solver."
Before/after: PPO vs random opponent 59.7% -> CNN distilled from solver
labels 96.3%.
Note: about 308k labelled positions plus mirror images; the network plays
without search.

10. Computer vision: localization
Title: "The board finds itself."
Before/after: tilted view -> detected holes -> fitted 6x7 lattice ->
3x3 homography -> rectified 700x600 board.
Manual fallback: 4 clicks in any order, canonicalized to TL/TR/BR/BL.

11. Computer vision: classification
Title: "Every cell becomes a color measurement that adapts to the light."
Visual: board with one zoomed cell.
HSV: red in two hue ranges (wrap at 0/180), yellow in one; ROI margin 20%,
fill threshold 30%.
Validated readings re-fit the bands; new thresholds are adopted only if
they reproduce the reading exactly.

12. Physical demo
Title: "From frame to AR arrow: validated transformations."
Sequence: capture -> vision -> validation -> perspective swap ->
safety net/agent -> column mirror -> AR arrow + voice.
Show the vision view and the agent view before/after swap_perspective().

13. Quality
Title: "Reliability didn't arrive at the end. It became a feature."
Metrics: 273 tests, CI on 3 operating systems, zero hardware in tests.
Three cases:
- ignored threat -> safety net + watchdog -> full-game tests;
- starved winning proof -> interleaved root search -> oracle test;
- dim light -> self-checking color adaptation -> rendered-scene tests.
Mention asynchronous, fail-soft TTS.

14. Roadmap and conclusion
Title: "The next step starts from real limits."
Roadmap:
P1 real webcam photos as tests, automatic re-localization;
P2 off-book coverage, fastest wins past the book;
P3 perfect play in the browser, ONNX export.
Final takeaway:
"Useful intelligence appears when perception, algorithms and
reliability are designed together - and measured."

Do not invent additional metrics. Keep diagrams technically correct, with
arrows in the direction described, and do not blur the distinction between
computer vision, the exact solver and the neural network.
```

## Review after generation

- Replace any stock images with diagrams or 6x7 boards.
- Check that Gamma does not present `neural` as the strongest tier
  (`impossible` is).
- Check that models receive a matrix, not a webcam image.
- Check that `swap_perspective` and the column mirror are two different
  transformations.
- Export to PowerPoint and check fonts, notes and alignment.
